# AGENTS — Agent operating rules (this workspace)

Loaded automatically by `dsh` (`agent-instructions`) on every session whose working
directory is here. These are instructions *to the agent* — they are lower authority than
the system prompt / persona and do **not** override direct user instruction. For the
human-facing "what is this repo and how do I use it," see the repo `README.md`.

---

## Identity model

**`dsh` is me.** When the agent acts here, it acts as the user — not as a separate
collaborator or assistant. So:

- **No authorship/attribution markers.** Do **not** add `Co-authored-by:`, "generated by
  dsh", or any commit-trailer that separates the agent from the user. Every commit is the
  user's own work.
- **No separate agent identity.** Do not use a distinct committer name/email for agent
  commits. Use the user's configured git identity.
- **Act with the user's voice and intent.** The agent is an extension of the user for
  agentic tasks, not a third party reporting back.

---

## Git conventions

- **Default branch is `master`** (never `main`). Every new repo/empty clone uses `master`.
- **One-line history / short commits.** Prefer concise one-line commit subjects; view
  history with the `lg` alias (`git log --oneline --graph --decorate --all`).
- **A reasonable commit-message shape** when it helps: a short imperative subject line
  (e.g. `feat: add profile page`), optionally a brief body for non-obvious changes.
- **Be deliberate, not messy.** Before committing, `git status` + `git diff` to confirm
  what changed. Keep commits focused and atomic — one logical change each.
- **Work on a feature branch** for non-trivial changes, so `master` stays reviewable and
  clean; fast-forward/merge deliberately.

---

## Quality posture (inherited from THINK.md)

- **Derive by default.** For novel, high-stakes, or uncertain work, reduce to fundamentals
  and reason from axioms rather than pattern-match.
- **Always slow in planning/thinking/design.** Where the outcome will be executed or is
  hard to undo, do not rush a decision. This matters most in this workspace.
- **Quality above cost.** Accept extra effort/tokens rather than a quick-but-weak answer,
  especially during planning and design.

---

## Workspace behavior

- This workspace is the `cwd` for sessions here. Context is scoped to this directory; a
  session's `cwd` is fixed at creation and can't be changed mid-session.
- Subdirectories (`ai/`, `rust/`) are not automatic workspaces of their own — they only
  become separate workspaces if a session is *started* inside them (different `cwd`).
- Skills live in `project` scope under `.dsh/skills/` (writable by the agent). Global
  skills under `~/.dsh/skills` are authored by the user (read-only to the agent sandbox).
- Cross-workspace access: **reads/searches are open**; **writes are confined to the
  workspace**. Reference other projects by absolute path (e.g. `~/codes/...`); do not
  assume the agent can write there.

---

## Review before shipping (even though dsh is me)

Since the agent acts as the user, "review" is a self-check, not a second opinion:
- On any non-trivial change, verify the diff and the outcome before committing.
- For anything executed forward (config, migration, destructive op), be explicit and
  careful — planning/thinking is always slow.
